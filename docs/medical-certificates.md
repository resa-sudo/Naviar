# Медицинские сертификаты: три фиксированных слота

Категория medical_certificates содержит ровно три независимых слота:

- medical_hiv_certificate — Сертификат об отсутствии ВИЧ.
- medical_infectious_diseases_certificate — Заключение об отсутствии опасных инфекционных заболеваний.
- medical_drug_screening_certificate — Заключение об отсутствии употребления наркотических / психотропных веществ.

Dropdown отсутствует. Окно всегда показывает все три строки, в том числе пустые. Файл добавляется из конкретной строки. При заполнении доступны просмотр, замена, удаление и ручные даты. Счётчик карточки 0/3–3/3; глобальный счётчик получает единицу за медицинскую категорию только при 3/3. Это означает заполненность файлами, а не проверку действительности документов.

## Хранение и API

Используется прежний upload pipeline: JPG/JPEG/PNG/PDF, максимум 10 МБ на файл, allowlist MIME/расширений, сигнатуры, UUID-имена, uploads вне static, один worker и RLock. В data/uploads/index.json медицинские файлы остаются списком, но для каждого нового фиксированного типа допускается только одна запись. Повторный POST в занятый слот возвращает 409; замена по ID сохраняет слот, создаёт новый ID и удаляет только прежний файл этого слота. Изменять слот через замену нельзя.

GET /api/documents/medical_certificates/slots всегда возвращает три состояния с medical_type, status, file_id, original_filename, uploaded_at, issue_date, valid_until, days_remaining. У пустых слотов status=not_uploaded, поля файла и даты — null. У загруженного status=uploaded; uploaded_at записывается в UTC. days_remaining вычисляется по локальной дате сервера из вручную указанного valid_until, без периодичности и без Rules Engine.

POST /api/documents/medical_certificates?medical_type=<фиксированный тип> добавляет файл через общий multipart обработчик. GET /api/documents/medical_certificates/{id}/file просматривает, PUT /api/documents/medical_certificates/{id} заменяет, DELETE /api/documents/medical_certificates/{id} удаляет один файл. PATCH /api/documents/medical_certificates/{id}/dates сохраняет issue_date и valid_until; пустые значения очищают даты. Дата выдачи не может быть в будущем, окончание — раньше выдачи. Замена файла очищает его прежние даты, чтобы не приписать их новому документу. Даты соседних слотов не меняются.

## Legacy

Старые записи medical_exam_certificate, additional_medical_certificate, other_medical_document и other_supported_medical_document сохраняются в исходной папке и индексе. Запись без типа читается как legacy_unassigned. Их нельзя автоматически интерпретировать как ВИЧ/инфекции/наркологию. Новый UI их не показывает и не учитывает в заполненности; старый ID остаётся доступен для просмотра через API. Чтение старого индекса не переписывает его. Новые загрузки generic-типов запрещены. Пользовательские uploads и index.json при разработке не менялись.

Это локальное MVP без авторизации/шифрования и crash-safe транзакций. Реальные медицинские документы не загружать. OCR медицинских файлов отсутствует. Rules Engine и Passport OCR не изменены.

## Проверки

108 серверных тестов и оба браузерных сценария прошли, включая настоящий локальный OCR, повторное распознавание, неподдерживаемый документ, ручное подтверждение и refresh. Проверены JPG/JPEG/PNG/PDF для каждого слота, независимость файлов и дат, legacy, счётчики 0/3–3/3 и 4/5→5/5 только при трёх файлах.
