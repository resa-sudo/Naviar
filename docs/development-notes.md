# NAVIAR Student v0.1

Локальное приложение для демонстрации интерфейса студента и загрузки тестовых документов.

## Запуск в Windows (PowerShell)

Используйте короткий путь, например C:\Projects\Naviar.

```powershell
cd C:\Projects\Naviar
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Если окружение уже создано, повторять команду venv не нужно. Откройте http://127.0.0.1:8000. Для остановки нажмите Ctrl+C в терминале сервера. Запускайте только один процесс Uvicorn, без --workers.

## Что работает

- Onboarding с обязательными полями и русским/английским интерфейсом.
- Профиль сохраняется в data/student/profile.json; авторизации и аккаунтов нет. Старый профиль из localStorage переносится однократно.
- Пять категорий: паспорт, виза, миграционная карта, регистрация и три медицинских слота внутри пятой категории.
- Окно выбора JPG/JPEG/PNG/PDF: имя, размер, превью изображения, удаление выбранного файла и отмена до отправки.
- Загрузка на локальный сервер, статус «Загружен», просмотр и удаление.
- Счётчик документов и уведомления без alert().
- Состояние документов сохраняется при обновлении страницы и перезапуске приложения.
- Ручное подтверждение полей паспорта, просмотр и редактирование, отдельный статус проверки.
- Опциональная кнопка «Распознать локально» в форме паспорта: найденные поля становятся черновиком, обязательное ручное подтверждение сохраняется.
- Помощник по-прежнему показывает демонстрационное сообщение, AI не подключён.

Для первых четырёх категорий предусмотрен один файл. Медицинская категория содержит три фиксированных слота с независимой заменой. Во время отправки кнопки временно блокируются, чтобы не отправить документ дважды.

## Где хранятся документы

Папка data/uploads/ создаётся автоматически при первой загрузке, вне app/static/.

- Файлы получают случайные UUID-имена с разрешённым расширением.
- index.json хранит тип документа, исходное отображаемое имя, размер, MIME-тип, серверное имя, статус и подтверждённые паспортные поля (отдельно от файла документа).
- Содержимое файлов и их метаданные не помещаются в localStorage. Профиль тоже хранится на backend; в localStorage данные больше не дублируются.
- При удалении сервер удаляет файл и его запись из индекса.
- Вся папка /data/uploads/ исключена через .gitignore, включая index.json и временные файлы. Пустой каталог хранить в Git не требуется.

Просмотр идёт через GET /api/documents/{type}/file; пути на диске клиенту не возвращаются.

## Только локальное MVP-хранилище

**Реальные паспорта, миграционные документы и персональные данные загружать нельзя. Используйте только демонстрационные файлы. Эта реализация не подходит для production.**

Без авторизации все браузеры, имеющие доступ к этому локальному серверу, видят один общий набор документов и могут его удалить. Профиль onboarding не является подтверждением личности и не ограничивает доступ. Не открывайте сервер в локальную сеть или интернет.

Сервер проверяет расширение, MIME-тип, фактическое количество байт и базовые сигнатуры содержимого. Разрешены image/jpeg, image/png, application/pdf, до 10 × 1024 × 1024 байт включительно. Общий multipart-запрос дополнительно ограничен этим размером плюс 64 КБ для служебных полей. Обрабатывается только один файл, дополнительные поля запрещены.

Проверка сигнатур не является полной проверкой структуры файла или антивирусом. PDF может содержать активные элементы; неизвестные файлы нельзя считать безопасными. Сервер не исполняет загрузки. Ответы просмотра имеют явный Content-Type, nosniff, no-store и ограничивающую Content-Security-Policy.

Имена с путями отклоняются. Путь формируется только из серверного UUID и проверяется на принадлежность каталогу uploads. Исходное имя используется только для отображения. Cross-site запросы браузера на изменение отклоняются, но это не заменяет авторизацию.

Нет шифрования файлов на диске, разграничения доступа, антивируса, резервных копий, аудита, лимитов частоты запросов или защиты от всех вариантов отказа в обслуживании. JSON-индекс обновляется через замену временного файла; блокировка работает только внутри одного процесса. При аварийном отключении во время операции возможны оставшиеся файлы .deleting или файлы без записи в индексе. Это не транзакционная база данных.

Облачные AI API, PostgreSQL, Staff-панель, облачные хранилища и внешние сервисы не подключены. Для тестовых изображений паспорта добавлен опциональный локальный PaddleOCR. Секреты и .env исключены из Git; на момент этого этапа проект не был опубликован.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты создают временное хранилище и отдельный сервер на свободном порту: документы работающего приложения не затрагиваются. Проверяются PNG/PDF, просмотр, перезапуск, удаление физического файла, неверные типы/сигнатуры, пустые файлы, пути, дублирование, граница 10 МБ, превышение лимита и cross-site запросы.

Для ручной проверки пройдите onboarding, выберите демонстрационный PNG/PDF, проверьте превью и размер, загрузите, обновите страницу, откройте документ и удалите. Счётчик должен изменяться вместе с карточками.

check_ui.mjs — дополнительный инструмент разработчика. Он требует Node.js, работающий NAVIAR на порту 8000 с пустым хранилищем и отдельный Chrome с портом отладки 9223. Используйте отдельный --user-data-dir внутри .browser-check/, а не личный профиль браузера. Запуск: node tests/check_ui.mjs. Созданные этим тестом документы удаляются в finally; снимки и тестовые файлы остаются в игнорируемой .browser-check/results/.

Проверка исключения загрузок из Git:

```powershell
git check-ignore data/uploads/index.json
git ls-files -- data/uploads
```

Первая команда должна показать путь, вторая — ничего.

Ограничение multipart-запросов использует штатный [RequestBodyLimitMiddleware Starlette](https://www.starlette.io/middleware/#requestbodylimitmiddleware).

## Дальнейшее развитие

Будущие сущности остаются Organization, Student, Document, Deadline, Rule и Staff. Приложение не привязано к одному университету; эти модели пока не вводились.

Следующий небольшой этап: ручное указание сроков действия тестовых документов и понятное отображение ближайших сроков. AI, OCR и реальные документы для этого не нужны. Перед работой с реальными данными потребуется отдельно спроектировать авторизацию, изоляцию пользователей и защищённое хранилище.

## Document Verification v0.1

Загрузка файла и подтверждение его данных — разные действия.

1. Новый файл и ранее загруженные файлы без статуса получают needs_confirmation («Требуется проверка»).
2. Только у паспорта доступна полноценная форма «Проверить данные». Пользователь вручную вводит восемь полей, отчество необязательно.
3. Сервер валидирует обязательные поля, длину текста и даты: рождение и выдача не в будущем, окончание срока строго позже выдачи. Юридической проверки действительности паспорта нет.
4. После подтверждения поля сохраняются в записи паспорта в data/uploads/index.json, отдельно от JPG/PNG/PDF. Эта же атомарная запись получает статус verified.
5. Кнопка «Данные» показывает сохранённые поля. «Редактировать данные» открывает заполненную форму; изменения записываются только при повторном подтверждении. Отмена ничего не меняет.
6. Удаление паспорта удаляет файл и всю его запись из индекса: поля и статус. Повторно загруженный паспорт начинает с needs_confirmation. Открытая до замены файла форма не может подтвердить новый файл.
7. Счётчик показывает количество загруженных файлов, а не проверенных документов. У остальных трёх типов остаётся «Требуется проверка», кнопка объясняет, что форма появится позже.

Статус «Проверен» означает только подтверждение введённых данных пользователем. Это не проверка подлинности, юридической действительности или актуальности документа.

Блок «Что мне делать сейчас?» учитывает отсутствие документов, непроверенные документы, подтверждённый паспорт и недоступность форм остальных типов. Он не сообщает, что все четыре документа проверены, когда подтверждён лишь паспорт.

### Модель и API

app/document_models.py содержит PassportData и DocumentStatus. Состояния uploaded, processing, needs_confirmation, verified, rejected и error зарезервированы для будущего общего процесса. Сейчас после загрузки сразу используется needs_confirmation, после ручного подтверждения — verified. Локальное распознавание паспорта теперь доступно через Document Engine. Остальные типы автоматически не обрабатываются.

PassportData отделена от HTML-формы: будущая обработка сможет подготовить те же поля для подтверждения. API:

- GET /api/documents — метаданные и статусы без паспортных полей.
- GET /api/documents/passport/data — данные для просмотра или заполнения формы.
- PUT /api/documents/passport/data — document_id загруженного файла и объект data; сервер проверяет их и подтверждает данные.
- DELETE /api/documents/passport — удаление файла, структурированных данных и статуса.

Форма не хранит паспортные поля в localStorage или sessionStorage. После закрытия значения очищаются из формы. Backend не пишет их в console/debug-логи; ответы валидации содержат только коды ошибок и имена полей, без присланных значений. Ответы API имеют Cache-Control: no-store.

**Это всё ещё локальное single-user MVP-хранилище без авторизации и шифрования. Реальные паспортные данные вводить нельзя. Используйте только полностью вымышленные значения и тестовые файлы.** Один набор данных доступен всем, кто может обратиться к локальному серверу. JSON-индекс не заменяет production-базу и не обеспечивает защищённое стирание данных с физического диска.

Индекс, его временные файлы и загрузки находятся внутри уже исключённой /data/uploads/. Дополнительного исключения .gitignore не требуется.

### Проверка подтверждения

Серверные тесты дополнены проверками обязательных полей, пробелов, дат, просмотра, редактирования, перезапуска, старого формата индекса, удаления и защиты от подтверждения заменённого файла.

Полный изолированный браузерный сценарий (требует уже установленных Chrome и Node.js):

```powershell
.\.venv\Scripts\python.exe tests/run_browser_tests.py
```

Команда запускает отдельные временные сервер и Chrome, использует полностью фиктивные паспортные значения и не затрагивает документы основного приложения. Проверяет форму, ошибки, подтверждение, просмотр, редактирование, отмену, обновление страницы, подсказки, удаление и прежнюю загрузку PNG/PDF/JPG. Временное хранилище удаляется после теста; снимки с вымышленными значениями остаются в игнорируемой .browser-check/results/.

## Медицинские сертификаты: фиксированные слоты

## Visa Intelligence v0.1 — текущий этап

Виза теперь имеет отдельную форму проверки и локальное OCR JPG/PNG через уже установленный PaddleOCR.
